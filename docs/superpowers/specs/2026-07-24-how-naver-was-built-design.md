# "어떻게 만들었을까" 시리즈 — 네이버 검색 편 설계

날짜: 2026-07-24
상태: 승인 대기

## 목적

네이버·카카오톡·유튜브·숲 같은 서비스가 어떻게 만들어졌는지 분석하는 블로그 글을 쓰고,
그 글을 바탕으로 유사한 스택의 클론 제품을 **배우면서** 만든다.
첫 대상은 네이버, 그중 **검색 엔진**이다.

핵심 제약:
- 서비스 목적 재현이 아니라 "만들면서 배우기"가 목표.
- Claude가 전부 만들지 않는다. 사용자가 직접 구현하도록 가르치는 방식으로 진행한다.
- 클론은 로컬에서만 동작하면 되지만, 실제 서비스 방법(배포·운영)은 항상 고려한다.
- 글을 먼저 작성·발행한 뒤 클론을 만든다.

## 산출물

1. 네이버 검색을 분석한 블로그 글 (github.io 발행)
2. 분석 글을 바탕으로 한 C++ 검색 엔진 클론 (로컬 실행, Docker 기반)

## 블로그

- **스택**: Jekyll + Mediumish 테마 (미디엄 느낌, GitHub Pages 네이티브 빌드 → push만으로 배포).
- **첫 글**: "어떻게 만들었을까 #1 — 네이버 검색"
  - 1999년 출발과 자체 검색엔진의 배경
  - 한글 검색이 왜 어려운가 (형태소 분석)
  - 크롤러 → 색인 → 랭킹 아키텍처
  - 현재 스택 개관
  - 말미에 클론 제작 예고로 다음 편 연결
- 글 언어: 한국어.

## 클론: C++ 검색 엔진

언어·도구를 네이버 실제 스택과 최대한 유사하게: **C++ 밑바닥 구현**, 인프라는 Docker.

파이프라인 4모듈, 모듈당 학습 루프 1회분:

| 모듈 | 역할 | 핵심 학습 |
|---|---|---|
| crawler | 한국어 위키백과 덤프 파싱 → 문서 저장소 구축 | 크롤러 구조(큐·중복제거·저장), 대용량 파일 처리 |
| indexer | 토크나이즈 → 역색인 생성 → 디스크 직렬화 | 한글 토크나이징, inverted index, 직렬화 |
| searcher | 쿼리 파싱 → 색인 조회 → 랭킹 | BM25/TF-IDF, 포스팅 리스트 병합 |
| web | HTTP 서버 + 네이버풍 검색 페이지 | HTTP 서빙(webserv 경험 연결), 서비스화 고려 |

- **코퍼스**: 한국어 위키백과 정적 덤프. 크롤러는 실제 HTTP 크롤러 구조를 흉내내되 입력은 덤프 파일 (법적·재현성 문제 없음).
- **형태소 분석**: 음절 n-gram + 간단한 조사 분리 규칙을 직접 구현. 완벽함보다 "한글 검색이 왜 어려운가"를 몸으로 배우는 것이 목적.
- **Docker**: 빌드 환경과 각 서비스가 컨테이너로 돌게 하여 "어떻게 서비스할 수 있을까" 관점을 유지.

## 티칭 방식 (모듈마다 반복)

1. **개념 설명** — 핵심 개념과 예시 코드를 먼저 설명
2. **사전 퀴즈** — 개념 이해 확인 후 진행
3. **빈칸 구현** — 구조·인터페이스·테스트는 제공, 핵심 함수 몸통은 TODO. 사용자가 직접 구현하고 테스트로 검증
4. **코드 리뷰** — 구현 완료 후 리뷰: 개선점과 실제 네이버 방식과의 비교

## 진행 순서

1. 블로그 세팅 (Jekyll + Mediumish, GitHub Pages 배포 확인)
2. 네이버 검색 리서치 → 분석 글 작성 → 발행
3. 클론 repo 세팅 (Docker 빌드 환경)
4. 모듈 1(crawler)부터 학습 루프 시작 → 순서대로 4모듈 완주

## 성공 기준

- `kyeonkim.github.io`에서 분석 글이 보인다.
- 로컬 Docker 환경에서 한국어 위키백과 일부를 색인하고, 웹 페이지에서 한글 질의로 관련 문서가 랭킹되어 나온다.
- 핵심 로직(토크나이저·역색인·랭킹)은 사용자가 직접 작성한 코드다.
